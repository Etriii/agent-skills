# Portable skill and integrity standard

Each shipping skill is `skills/<name>/SKILL.md` plus `metadata.toml`. Names use lowercase ASCII letters/digits separated by single hyphens, at most 64 characters. Folder, frontmatter name and stable `skill_id` match. Frontmatter contains only name and a useful plain scalar description; instructions state inputs, outputs, evidence and limits without a private runtime dependency.

Metadata schema 1 fields are `skill_id`, `name`, `version` (three integer components), nonempty `capabilities`, `compatible_agents`, `license_status`, and `provenance`. Current content is version 0.1.0 with license UNDECIDED for locally authored material. Provenance is `local-authored`, or `local-with-third-party` when licensed upstream material is bundled. Mixed-source skills require `third_party_notices = "THIRD_PARTY.md"` and that file in the payload; it identifies copied material and links bundled licenses. This does not select a collection license or relicense upstream content. Compatible agent names record only verified discovery adapters. See `COMPATIBILITY.md`; an empty list means unverified. An approved license requires an explicit metadata/validator/documentation update and owner-selected license file before distribution.

`SHA256SUMS` lists lowercase file SHA256 plus two spaces and a repository-relative path. Every file in a selected skill must be listed exactly once and match; omitted or extra files fail. The installer never executes payload scripts. Deep Critique includes standard-library report-storage helpers, invoked explicitly by the agent when saving assessments. Directory links, junctions, special files, traversal and duplicate manifest entries fail closed. `.gitattributes` fixes payload line endings to LF so archive and checkout bytes agree.

The displayed tree digest hashes sorted file digest/path records followed by sorted `dir  <relative-path>` records, all UTF-8 with LF. It includes empty directories to preserve custom additions. It is distinct from the manifest file's SHA256 and from Git revision IDs. Installation checks staged and installed tree digests against the manifest-verified source snapshot.

Each skill also includes a human-facing `README.md` with installation, invocation and prerequisites. It is part of the validated payload and must appear in `SHA256SUMS`. After an intentional skill edit, follow the collection [contribution guide](../../../CONTRIBUTING.md#refresh-integrity-manifests) to regenerate the selected pack's manifest from the collection root, then review the hashes and run the documented checks.

The [usage documentation contract](../../../CONTRIBUTING.md#document-skill-commands-and-automation) also requires clear defaults, supported commands/options, expected outputs and writes, approval/continuation behavior, prerequisites, and stopping conditions. Document continuous execution only when supported. Use the [command guide](../../../docs/SKILL_COMMANDS.md) for discovery; each installed README must still explain its own usable request and effects without depending on the collection checkout.

Installation examples follow the [direct-install documentation rules](../../../CONTRIBUTING.md#document-installation-without-hidden-setup): npx first, no manual checkout prerequisite for ordinary skills, explicit shell/folder/agent/scope/result instructions, and optional Python examples only after explaining local checkout acquisition and its root. Do not invent curl bootstrap scripts or hide required runtime assets.

The validator intentionally supports this constrained portable frontmatter rather than general YAML. Tests exercise actual installation outcomes and integrity failures using only Python's standard library. Native discovery checks are optional environment proof, recorded separately. Never infer a publishing license or trusted source identity from a filename, prefix, checksum or synthetic fixture.
